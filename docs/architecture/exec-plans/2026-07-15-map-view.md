## Goal & non-goals

The Accueil tab gains a **list ⇄ map switch**. In map mode, every available deal is
a brand-red price bubble at its merchant's real Toulouse location; the category
filter still applies and filters the bubbles; selecting a bubble draws a **road
route** from the user to that merchant and shows distance + ETA. Done means: on a
device, switching to map shows bubbles, tapping a filter removes non-matching
bubbles, and tapping a bubble draws a red route from the blue dot.

**Non-goals.** No merchant-side map, no live delivery tracking, no turn-by-turn
navigation, no custom Mapbox Studio basemap (standard style + brand overlays —
the Studio style URL is a later one-line swap). No backend: merchant coordinates
stay static in `catalog.ts`, like the rest of the demo catalog.

## Risks & landmines

- **Native module ⇒ no hot reload.** Nothing in Phases 3–4 is visible on the current
  dev client. A fresh dev build (T4) gates all UI feedback. Budget ~10 min per build.
- **Two different Mapbox tokens.** Public `pk.*` renders the map and is _meant_ to ship;
  secret `sk.*` (DOWNLOADS:READ) is build-time only and must live as an EAS secret.
  Never commit either.
- **`check-secrets` false positive.** `scripts/check-secrets.mjs` flags any
  `EXPO_PUBLIC_*` name containing `TOKEN` — so `EXPO_PUBLIC_MAPBOX_TOKEN` would fail
  `verify` and block the pre-commit hook. Read the token in `app.config.ts` at build
  time and pass it via `extra` instead; do not weaken the rule.
- **Directions API is a network call** on a catalog that is otherwise fully offline.
  It must fail soft: no route ⇒ still show the bubble and the straight-line distance.
- **Disk at 98%.** Local bundling has already died once with `no space left on device`.
  EAS builds are unaffected (cloud), local Metro is not.
- **`packs/` is ESLint/tsconfig-excluded** — importing from it in app code is banned by
  the boundaries rule. Port the helper into `src/`, don't import across.
